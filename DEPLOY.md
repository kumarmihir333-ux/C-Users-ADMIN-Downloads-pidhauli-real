# Put Pidhauli online with Render

This project uses Flask and SQLite. The Render configuration keeps the SQLite
database on a persistent disk, so account and saved-field data survives service
restarts. The persistent disk requires Render's paid Starter service.

## Before deploying

1. Keep the GitHub repository **private** while it contains application code.
2. Do not add `database/pidhauli.db`, `.env` files, API keys, passwords, or
   customer data to GitHub. The `.gitignore` file excludes the local database
   and environment files.
3. Create a private GitHub repository and upload the project files. Include
   `app.py`, `routes/`, `templates/`, `static/`, `database/schema.sql`,
   `requirements.txt`, `wsgi.py`, `render.yaml`, `.gitignore`, and this guide.
4. In Render, choose **New → Blueprint**, connect the private repository, and
   select `render.yaml`.
5. When Render asks for secret values, set `ADMIN_EMAIL` and a new,
   unique `ADMIN_PASSWORD` of at least 12 characters. Optionally set
   `ADMIN_NAME` and your OpenWeather key. Never reuse a password from this
   project or send secrets in chat.
6. Deploy. Wait for `/healthz` to report healthy, then open the HTTPS URL
   Render displays.

`FLASK_SECRET_KEY` is generated by Render and must remain stable so sign-ins
survive restarts. `DATA_DIR` points to Render's persistent disk. The first
startup creates the schema and the admin account from the environment settings.
That admin account is created only if its email is not already in the database;
changing the environment password later will not reset an existing account.

The local `database/pidhauli.db` is not uploaded or copied. The hosted app starts
with the sample market data in `schema.sql` and a new, empty user database.
